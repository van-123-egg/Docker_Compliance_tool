# How to Test the Docker CIS Compliance Tool

This guide walks you through manually testing all features of the Docker CIS Compliance Scanner using the built-in test environment.

## 1. Start the Test Environment

We have provided a Docker Compose environment that spins up two intentionally crafted containers:
1.  **`cis_test_vulnerable`**: An app with numerous security violations (runs as root, privileged, exposes SSH, bad Dockerfile practices).
2.  **`cis_test_secure`**: A fully compliant, locked-down application.

Open your terminal (PowerShell or Command Prompt) and navigate to the project root, then bring up the environment:

```bash
cd test_env
docker-compose up -d --build
cd ..
```

Verify they are running:
```bash
docker ps
```
*You should see `cis_test_vulnerable` and `cis_test_secure` running.*

---

## 2. Run Basic Scans

The tool requires administrative privileges to inspect host files and docker daemons. Ensure you run this in an Administrator terminal.

### Run a Full Suite Scan
Run all checks (Host, Daemon, Socket, Containers, Images, and Dockerfiles) and view the results in your terminal:

```bash
python main.py --suite all --format table
```

### Run a Specific Suite
If you want to focus on a specific area, you can isolate the scan using the `--suite` flag:

```bash
# Check only running containers
python main.py --suite container --format table

# Check only Dockerfiles (via Image History)
python main.py --suite dockerfile --format table
```

---

## 3. Test the Reporting Formats

The tool supports four different output formats. Try generating each one:

### 1. Interactive HTML Report (Recommended)
This generates a beautiful, interactive dashboard using Chart.js.

```bash
python main.py --suite all --format html
```
*Open `compliance_report.html` in your web browser to view the dynamic charts and detailed remediation steps.*

### 2. PDF Report
This generates a formatted, printable PDF with text-wrapped tables and color-coded severities.

```bash
python main.py --suite all --format pdf
```
*Open `compliance_report.pdf` to view the document.*
If you want to generate the report in your naming convention, you can use the following command:

```bash
python main.py --suite all --format pdf --output <your_report_name>.pdf
```

### 3. JSON Output
Useful for integrating with external tools or CI/CD pipelines.

```bash
python main.py --suite all --format json --output raw_report.json
```
*View `raw_report.json` to see the machine-readable output.*

---

## 4. Test Scan History & Diff Engine

The tool automatically saves every scan run to `~/.docker-compliance/scans/`. You can view your scan history and compare scans to track security regressions or improvements.

### View Scan History
See all the scans you've run so far:

```bash
python main.py --history
```

### Compare Current Scan to Previous Scan
Stop the vulnerable container to simulate fixing security issues:

```bash
docker stop cis_test_vulnerable
```

Now, run a comparison against the last saved scan to see the improvements:

```bash
python main.py --compare
```
*You should see a side-by-side comparison showing an improved compliance score and fewer failed checks.*

---

## 5. Test CI/CD Strict Mode

You can test how the tool behaves in an automated pipeline (where exit codes matter).

### Default Mode (Fails on CRITICAL/HIGH)
By default, the tool exits with code `1` if there are any CRITICAL or HIGH failures, and code `2` for MEDIUM/LOW.

```bash
python main.py --suite all
echo $?   # On Windows PowerShell: echo $LASTEXITCODE
```

### Strict Mode (Fails on ANY Failure)
Force the tool to fail the build if there is *any* violation, no matter the severity:

```bash
python main.py --suite all --strict
```

## What to Look For During Testing

When reviewing the HTML/PDF reports or the terminal output, check for these specific findings generated by the `cis_test_vulnerable` container:

*   **DL-02 / 4.1**: Running as `root` user.
*   **5.5**: Running with the `--privileged` flag.
*   **5.6**: Dangerous host mount (`/:/hostfs`).
*   **5.32**: Mounting the docker socket (`/var/run/docker.sock`).
*   **DL-04**: Exposing Port 22 (SSH).
*   **DL-08**: Storing `API_SECRET_KEY` in an `ENV` variable.

If you see these flagged as **FAIL** with the exact remediation commands, the tool is working perfectly!

## Prometheus & Grafana Monitoring

The tool can optionally expose compliance metrics to **Prometheus** for scraping, with a pre-built **Grafana** dashboard for visualization.

### 1. Install the Prometheus Client Library

```bash
pip install prometheus_client>=0.20.0
```
*(Or just run `pip install -r requirements.txt` to install all dependencies.)*

### 2. Start the Monitoring Stack

```bash
cd monitoring
docker compose up -d
```

This launches:
- **Prometheus** at `http://localhost:9090`
- **Grafana** at `http://localhost:3000` (login: `admin` / `admin`)

### 3. Run the Tool with Metrics Enabled

**Single scan** (metrics are available until you close the terminal):
```bash
python main.py --suite all --format table --metrics
```

**Continuous scanning** (re-scans every 60 seconds, keeps metrics live):
```bash
python main.py --suite all --format table --metrics --metrics-interval 60
```

**Custom port**:
```bash
python main.py --suite all --format table --metrics --metrics-port 9100
```
> **Note:** If you change the port, also update `monitoring/prometheus.yml` to match.

### 4. Verify Metrics

| What to Check | URL | What You Should See |
|---|---|---|
| Raw metrics | `http://localhost:8000` | Prometheus text format with `compliance_*` metrics |
| Prometheus targets | `http://localhost:9090/targets` | `docker-compliance-scanner` target showing **UP** |
| Prometheus query | `http://localhost:9090/graph` | Query `compliance_score_percent` → returns a value |
| Grafana dashboard | `http://localhost:3000` | Navigate to **Docker CIS Compliance** dashboard |

### 5. Available Metrics

| Metric | Description |
|---|---|
| `compliance_score_percent` | Overall compliance score (0–100%) |
| `compliance_checks_failed` | Total failed checks |
| `compliance_failures_by_severity{severity="CRITICAL\|HIGH\|MEDIUM\|LOW"}` | Failures by severity |
| `compliance_suite_duration_seconds{suite="..."}` | Per-suite scan time in seconds |

### 6. Stop the Monitoring Stack

```bash
cd monitoring
docker compose down
```
